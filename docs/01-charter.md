## 1. 机会从哪里来：生态位分析

### 1.1 方法

对近期新出现的开源项目做横向扫描与聚类，先看「哪些问题正在被反复解决、
但还没有收敛成整体方案」，再决定做什么，而不是先定方向再找证据。刻意排除
已经高度拥挤的 AI / LLM / MCP 工具链、同质化的加密货币机器人，以及无法在
本机闭环验证的方向。

### 1.2 聚类结论

> **一个 CGO-free 单二进制 = 守护进程 + 嵌入式数据库 + Web 控制台，
> 常同时带 TUI/CLI，面向自托管运维场景。**

### 1.3 BastionDeck 吸收的局部设计（按主题，不指名具体项目）

- **一守护进程多界面**：Web/TUI/CLI 共用同一套 API；本地控制面走 Unix socket，不绑公网 TCP；CGO-free 单二进制；配置变更原子、可回滚。
- **主机操作面**：分组/标签/收藏/备注/搜索/ssh config 导入/跳板链；Web 终端；SFTP 浏览与传输；本地/远程隧道；变量化片段；多机执行必须**显式选目标 + 广播指示 + 紧急停止**；主机密钥 TOFU。
- **凭据与授权**：AES-256-GCM 凭据保险库（仅连接时解密、AAD 绑定）；执行权与配置管理权分离；审计到真实退出码、stdout/stderr 分离；文件原子写 + sha256 乐观锁；跳板限深禁环；连接复用；任务 `lost` 失联态。
- **可靠任务面**：先持久化再动作；重投递幂等；结果不明挂起；容量/并发预算；对账循环；`doctor` 自检；核心与适配器分离。
- **fleet 治理**：owner/admin/operator/viewer 四级 RBAC 与会话撤销；加密备份先暂存校验后恢复；危险操作带回滚窗口与重读确认；脱敏诊断。
- **安全默认值**：argon2id + RFC6238 TOTP；滑动会话与强制下线；自定义头 CSRF（不开 CORS）；登录限流；审计游标分页/导出/保留；SSE 事件总线；乐观更新只到过渡态；首次启动 setupRequired 防抢注；CSP 完全离线；go:embed 前端。

## 2. 问题陈述

个人开发者、小团队 SRE、Homelab 玩家通常同时管理 3～50 台 Linux 主机（VPS、NAS、软路由、开发板、家中旧机器）。现状是在五六个工具之间反复横跳：

- 终端（iTerm/Windows Terminal）+ 单独的 SFTP 客户端（FileZilla/WinSCP）；
- 记不住的 IP/密码/密钥散落在 Excel、ssh config、聊天记录里；
- 想对 10 台机器批量执行一条命令，要么手写 for 循环，要么上 Ansible 这类重型工具；
- 端口转发要用独立命令维护，关了终端就断；
- 谁在什么时候对哪台机器执行了什么，没有审计；
- Web 化的方案（JumpServer、Teleport、Guacamole）重、要多个容器、要外部数据库、学习成本高；
- 这些能力散落在不同工具里，**缺少一个把它们收敛成「一个二进制、五分钟跑完、Web/TUI/CLI 三界面一致」的整体**。

## 3. 产品定义

### 3.1 一句话定义

BastionDeck 是一个 **CGO-free 单二进制、自托管、无外部依赖的「主机舰队」运维管控台**：在一台跳板机上启动后，通过浏览器、终端 TUI、命令行 CLI 三种界面管理你的全部 SSH 主机——凭据加密托管、Web 终端、文件管理、端口隧道、命令片段、多机批量任务、定时任务、主机指标、完整审计，可选安装 bd-agent 纳管无法 SSH 的机器。

### 3.2 目标用户与典型场景

| 用户 | 规模 | 典型场景 |
|---|---|---|
| 独立开发者 / 自由职业 | 2～10 台 VPS | 一台 Web 终端直接操作，凭据不再散落 |
| 小团队 SRE / 创业公司 | 10～50 台 | 新人按角色登录看主机；批量执行滚动命令；审计谁执行了什么 |
| Homelab / 自托管玩家 | 5～30 台异构设备 | TUI 在 SSH 会话里快速操作；隧道一键开关；定时备份脚本 |
| 教学 / 实验环境 | 一个机房的虚拟机 | 讲师 operator 角色可执行，学生 viewer 只读观摩 |

### 3.3 功能范围（MoSCoW）

**M（Must，本次交付）**

1. 首次启动向导：setupRequired 状态、创建 owner、生成/指定主密钥，防止安装阶段被抢注。
2. 用户与 RBAC：owner/admin/operator/viewer 四角色，会话滑动过期、强制下线；TOTP 双因子。
3. 主机清单：增删改查、分组、标签、备注、收藏、最近连接、全文搜索；OpenSSH `~/.ssh/config` 导入；跳板链（≤5 级、禁环）。
4. 凭据保险库：密码/私钥 AES-256-GCM 加密，主密钥派生，AAD 绑定凭据 ID，仅建立连接时解密；列表永不回显明文。
5. 主机密钥信任：首次连接 TOFU 记录指纹，指纹变更默认拒绝、显式重置。
6. 连接测试与连接池：15s 建连预算、keepalive、按主机复用、显式关闭。
7. Web SSH 终端：xterm.js → WebSocket → SSH PTY，支持 resize、多标签页。
8. 文件管理：SFTP 列目录、上传/下载（进度、可取消、并发有界）、文本在线编辑（sha256 乐观锁、原子写）、权限保留。
9. 命令片段：变量 `${host}`/`${user}` 等、发送前预览、标签分类。
10. 多机批量执行：**必须显式勾选目标**、界面常驻广播指示、一键紧急停止；逐主机独立状态与真实退出码，stdout/stderr 分离。
11. 后台任务与定时任务：一次性后台 Job、cron 风格定时；状态机 `pending→running→success/failed/timeout/cancelled/lost`；增量日志、kill；服务重启后不明结果标 `lost`。
12. 端口隧道：本地转发 / 远程转发的创建、状态、停止。
13. 主机指标：Linux `/proc` 采集 CPU/内存/负载/磁盘，7 天保留。
14. 审计：所有写操作与执行留痕，**审计记录哈希链**（每条含前一条哈希，篡改可检测），游标分页、导出、保留策略；敏感字段只记长度。
15. 三界面一致：Web（全功能）、TUI（主机/执行/任务高频路径）、CLI `bdk`（脚本化），后两者经本地控制面 Unix socket 或 HTTP+Token 调同一套 API。
16. 加密备份/恢复：导出加密包，恢复先在暂存区校验再提交。
17. `doctor` 自检：数据目录、主密钥、迁移版本、端口占用、磁盘空间、时间回拨检查。
18. bd-agent（项目二）：无法走 SSH 时，agent 反向注册到服务端，上报事实信息、指标，接收执行指令；服务端 connector 层对 SSH/Agent 两种后端透明。

**S（Should，时间允许则做）**

- 跨主机文件传输（A→经跳板→B）；主机间命令结果对比视图；审计时间线 SSE 实时流。

**C（Could，预留不实现）**

- RDP/VNC、串口、X11（都是独立大工程，明确列为非目标）；云厂商 API 纳管；移动端原生 App。

**W（Won't，本期明确不做）**

- **任何 AI/LLM/MCP 能力**；多节点集群与横向扩缩容（定位单机）；对公网暴露的托管服务。

### 3.4 差异化定位

| 维度 | JumpServer 等重型堡垒机 | 桌面 SSH 客户端（MobaXterm/Tabby 等） | 单点小工具 | **BastionDeck** |
|---|---|---|---|---|
| 部署 | 多容器+外部 DB | 本机 GUI 安装 | 单二进制但只解决一块 | **单二进制、数据全在一个目录** |
| 界面 | Web | 桌面 GUI | Web 或 TUI 之一 | **Web + TUI + CLI 三界面同一控制面** |
| 多机批量 | 有但重 | 部分支持 | 多面向机器而非操作者 | **面向人，显式目标+广播指示+急停** |
| 凭据 | 服务端托管，重 | 本地 | 保险库模型新但无 TUI/文件管理 | **保险库 + TOTP + RBAC + 哈希链审计** |
| 离线/内网 | 可以 | 可以 | 部分 | **前端零外部资源，CSP self，断网可用** |
| AI | 部分在加 | 部分在加 | 绝大多数在卷 AI | **刻意无 AI，操作语义 100% 确定** |

一句话护城河：**把分散在各类小工具里、已被反复验证的优秀局部设计，收敛为一个「部署一分钟、三界面一致、安全默认值拉满」的整体，每一个安全/可靠性决策都有明确的工程理由。**

## 4. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 后端语言 | Go 1.23，CGO-free 静态二进制 | 交叉编译无痛、部署物最小、并发与网络生态成熟 |
| HTTP | 标准库 `net/http`（Go 1.22+ 方法路由） | 不引 Web 框架，依赖树最小 |
| 数据库 | SQLite，驱动 `modernc.org/sqlite`（纯 Go） | 单机场景足够、免 CGO、零外部依赖 |
| SSH | `golang.org/x/crypto/ssh` + `pkg/sftp` | 事实标准，纯 Go |
| WebSocket | `github.com/coder/websocket` | 轻量、context 优先，供终端与实时推送 |
| 口令/密钥 | `x/crypto/argon2`（argon2id）、AES-256-GCM（stdlib crypto/aes） | 现代口令哈希与认证加密的标准档位 |
| TOTP | 自实现 RFC 6238（stdlib crypto/hmac） | 避免引入多余依赖，行为可测 |
| 前端 | React 18 + TypeScript + Vite | 生态成熟、构建快、类型可与后端 DTO 对齐 |
| 终端组件 | xterm.js | 浏览器终端事实标准 |
| 状态管理 | 自研 useSyncExternalStore store | 零额外依赖，CSP 下可离线 |
| 样式 | 手写 CSS（浅/深/跟随系统三档） | 无外部字体/CDN，完全离线 |
| TUI | `x/term` + 自绘 ANSI（不引 tcell/bubbletea） | 控制依赖体积，实现列表/详情/执行视图即可 |
| 测试 | Go testing（含进程内 SSH 伪主机做集成测试）+ Vitest | 用 loopback 协议夹具，测试不依赖真实主机/个人 ~/.ssh |

## 5. 非目标（Non-Goals）与边界

1. 不是 hostile-code 沙箱：它约束和审计被授权的运维动作，不阻止操作者主动做破坏。
2. 不替代监控系统：只保留 7 天轻量 /proc 指标，不做长期时序库。
3. 不做 SSH 协议本身的实现，使用 x/crypto/ssh。
4. 不向任何第三方上报；前端不加载任何外部资源。
5. bd-agent 不做隐蔽安装、不做提权、明文不离开本机、服务端可一键吊销。

## 7. 风险登记册

| 风险 | 等级 | 对策 |
|---|---|---|
| x/crypto/ssh 行为与真实 OpenSSH 差异 | 中 | 进程内 SSH 服务器覆盖协议路径；另用本机 ssh 客户端做 loopback 冒烟；差异点写入已知限制 |
| 纯 Go SQLite 在高并发写时锁库 | 中 | 单写者 goroutine + WAL；任务日志走批量提交；压测验证 |
| Web 终端在断线重连后状态错乱 | 中 | 终端会话与 HTTP 会话解耦，重连只重绑 PTY；明确显示重连态并清理过期帧 |
| 20k 行目标膨胀为堆代码 | 中 | 每个模块都对应 §3.3 的功能点；用测试与文档支撑代码，不写无调用方的死代码；LOC 每周统计，不足再按用户授权追加项目二 |
| 前端 npm 依赖供应链 | 低 | 依赖白名单（react/react-dom/router/xterm/vitest 等少量），构建产物离线自包含 |
| 时间回拨导致 TOTP/审计链异常 | 低 | doctor 检测单调钟；HLC 风格时间戳在任务对账中容忍回拨 |
| 范围蔓延（用户中途加需求） | 低 | 以本 Charter 为基线，新增进 C/W 区或另开 ADR |

## 8. 验收标准（与最终验收文档对应）

1. 功能：§3.3 M 区 18 项全部可从真实入口（HTTP/WS/CLI/TUI）触发并观察到结果。
2. 代码量：两项目源码（去注释空行后）合计 ≥ 20,000 行，以脚本实数为准。
3. 质量：`go test ./...` 全绿、`go vet ./...` 无告警、关键包 `-race` 通过；前端 `tsc --noEmit`、`vitest run`、`vite build` 全绿。
4. 运行：单二进制启动 → 初始化 → 登录 → 添加进程内/本机主机 → Web 终端执行命令 → 批量任务 → 文件编辑 → 审计导出，全链路冒烟通过并留证。
5. 文档：立项、架构、API 契约、验收报告齐备，每个设计决策在 §1.3 有对应的工程理由。
